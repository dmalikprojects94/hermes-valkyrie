# Final Report Format

For every substantial run, finish with these exact headings in this exact order:

## Request

State what was asked.

## Changes

State what was changed, created, deleted, or intentionally left untouched.

## Verification

State the concrete checks you ran and what they returned.

## Blockers

State anything that failed, remains uncertain, or still needs operator input. If nothing is blocked, write `None.`

## Next Steps

State the next concrete action for Hermes or the operator. If nothing remains, write `None.`

## Provenance

- Source: internal Hermes-operator runtime-surface design.
- Disposition: runtime-specific-adapter for Claude Code baseline.
- Notes: baseline file copied into every Claude materialized loadout before named overlays.
