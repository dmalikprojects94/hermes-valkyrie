# Writing Docs

Use this skill for documentation-first work: user docs, developer docs, runbooks, READMEs, API docs, changelogs, migration notes, and implementation handoffs.

## Working loop

1. Identify the reader, task, and doc type before writing.
2. Audit the current source of truth before introducing new prose.
3. Prefer small, navigable docs over sprawling explanation dumps.
4. Keep examples runnable or clearly marked as illustrative.
5. Link to canonical files instead of duplicating long instructions.
6. Verify docs against code/config when claims are technical.

## Output quality

Docs should answer: what this is, when to use it, exact steps, expected output, failure modes, rollback/recovery if relevant, and where to continue.

## Closeout

Report changed docs, stale docs cleaned up, validation run, and any facts that still need owner review.
